## 2. API Integrations and Authentication

### 2.1. Spotify Web API
* **Prerequisites:** Active Spotify Developer App.
* **OAuth Flow:** `SpotifyPKCE` (does not require `CLIENT_SECRET` exposed in local scripts).
* **Redirect URI:** `http://127.0.0.1:8888/callback` (explicit loopback IP).
* **Required Scope:** `playlist-read-private playlist-read-collaborative`
* **Extraction Endpoint:** `GET /v1/playlists/{playlist_id}/items` (supports pagination with `limit=50` and `offset`).
* **Playlist ID Parsing:** Supports raw IDs (`37i9dQZF1DX...`) and full URLs (`https://open.spotify.com/playlist/...`) parsed via Regex.

### 2.2. GetSongBPM API
* **Base URL:** `https://api.getsong.co`
* **Auth:** Query parameter `api_key={GETSONGBPM_API_KEY}`
* **Search Endpoint:** `GET /search/`
  * `type=both`
  * `lookup=song:{clean_title} artist:{primary_artist}`
  * `limit=3`
* **Cleaning & Caching Strategy:**
  * **Rate Limiting:** Sleeps 0.2s between external calls and caches results in `cache/getsongbpm_cache.json` indexed by `spotify_id`.
  * **Title Normalization:** Strips common Spotify suffixes before searching (`- Radio Edit`, `- Original Mix`, `- Remastered`, `(feat. ...)`).
  * **Data Mapping:** Extracts `tempo` (BPM), `key_of` (e.g. `"Am"`), `open_key` (e.g. `"1m"`), and converts to `camelot_code`.

## 4. Transition Scoring and Rules (`src/camelot.py` & `src/evaluate_setlist.py`)

### 4.1. Open Key / Key -> Camelot Conversion
Maps 24 Open Key and standard musical keys into Camelot codes (`1A` to `12B`):
* `1m` (Am) = `8A` | `1d` (C) = `8B`
* `2m` (Em) = `9A` | `2d` (G) = `9B`
* Full 24-key dictionary in `src/camelot.py`.

### 4.2. Scoring Matrix (`Track A -> Track B`)

| Criterion | Rule | Status |
| :--- | :--- | :--- |
| **Perfect Harmony** | `camelot_A == camelot_B`, adjacent `±1` on same letter (e.g. `8A -> 9A`), or relative (`8A -> 8B`) | `IDEAL` |
| **Energy Boost** | Leap of `+2` (e.g. `8A -> 10A`) or `+7` (e.g. `8A -> 3A`) on same letter | `GOOD (BOOST)` |
| **Harmonic Clash** | Any other distance on Camelot wheel | `CRITICAL ALERT` |
| **Comfortable Tempo** | `abs(bpm_B - bpm_A) / bpm_A <= 0.035` (up to ±3.5% pitch) | `IDEAL` |
| **Moderate Tempo** | Variation between `3.5%` and `6.0%` | `WARNING` |
| **Abrupt Tempo Shift** | Variation `> 6.0%` | `CRITICAL ALERT` |

### 4.3. Counterproof Logic
When a transition triggers `CRITICAL ALERT`:
1. **Half/Double Time Check:** Checks if `abs((bpm_B * 2) - bpm_A) / bpm_A <= 0.04` or `abs((bpm_B / 2) - bpm_A) / bpm_A <= 0.04`. If true, reclassifies to `WARNING (Half/Double Time compatible)`.
2. **Internal Reordering Suggestion:** Searches other tracks `k` in the playlist where `Track i -> Track k` yields `IDEAL` or `GOOD (BOOST)` for both key and BPM.
3. **Missing Data Handling:** Tracks with `found == false` are isolated under `MISSING DATA` to avoid skewing overall evaluation metrics.
